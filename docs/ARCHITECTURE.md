# Nano Java architecture

Nano Java runs J2ME MIDlets (CLDC 1.1 / MIDP 2.0). It was written for the
Nintendo DS; pico-j2me ports it to RP2350 boards (Murmulator and friends)
with QSPI PSRAM. It has three layers:

```
 classlib/src   Java: java.lang, java.util, java.io, javax.microedition.*,
                com.nokia.mid.*, nanojava.* (glue)        -> classlib.jar
 src/           C99, portable: the VM (src/vm), ZIP/inflate/PNG (src/util),
                MIDP natives and the rasterizer (src/midp)
 platform/      one directory per target, implementing src/pal/pal.h:
                host (headless, for tests) and rp2350 (Pico SDK)
```

Everything the C code needs from a machine is in `src/pal/pal.h`: time,
console output, input events, presenting a frame, a data directory and a
fatal error screen; and in `src/pal/pal_sys.h`: native memory
(`pal_malloc`... and `pal_heap_alloc` for the Java heap arena) and files
(`pal_fopen`..., `pal_opendir`...). The portable code never calls malloc or
stdio itself. Porting to a new target means implementing those functions
and a `main` that starts the VM.

## The VM (src/vm)

| File | Role |
|---|---|
| `vm.h` | All core types (`Object`, `Class`, `Method`, `Thread`, `Slot`...) and the internal API |
| `classfile.c` | Parses class files into unlinked `Class` structures |
| `class.c` | Loading, linking (field layout, vtables, native binding), lookups, subtype checks, `java.lang.Class` mirrors |
| `interp.c` | The interpreter, invocation, class initialization, exceptions |
| `thread.c` | Green threads, monitors, `wait`/`notify`, `sleep`, the scheduler |
| `heap.c` | Java heap and mark & sweep collector |
| `string.c` | `java.lang.String` helpers and the intern table |
| `natives_lang.c` | Natives of `java.lang` and `nanojava.*` |
| `resource.c` | Where classes and resources come from (class library, application jar) |
| `vm.c` | Start-up: core classes, the boot thread |

Key design points:

- **Values are `Slot`s** (a union of int, float and reference, pointer
  sized). `long`/`double` take two slots. Object fields, statics, locals
  and the operand stack all use slots.
- **No C recursion for Java calls.** Invoking a method pushes a `Frame` and
  the interpreter loop continues. The caller's `pc` stays on its invoke
  instruction while the callee runs, which keeps exception ranges exact;
  the callee's `ret_skip` says how far to advance on return.
- **Re-executable instructions.** Anything that has to wait (a class
  initializer, a contended monitor, `sleep`, `wait`, waiting for input)
  leaves `pc` unchanged and returns to the scheduler; the instruction runs
  again later. Natives do the same by returning `NATIVE_BLOCK`, keeping
  their progress in `Thread.native_phase`. `NATIVE_INVOKE` lets a native
  finish by calling a Java method (`Class.newInstance` runs the
  constructor this way).
- **Green threads.** One native thread; the scheduler runs each Java thread
  for a slice counted in backward branches and calls.
- **Garbage collection.** Non-moving mark & sweep over one arena with
  segregated free lists. Object fields are traced precisely (each class
  records its reference slots); thread stacks, statics and the C stack are
  scanned conservatively, made safe by a bitmap of object start
  addresses. `WeakReference` referents are cleared after marking.
- **Symbols.** Names and descriptors are interned, so lookups compare
  pointers.

## Class library (classlib/src)

Written in Java, compiled by javac (JDK 8) with `-source 1.3 -target 1.3`
against itself, and packed into `classlib.jar` (linked into the firmware's
flash; `classlib/classlib.jar` is a prebuilt copy for builds without a JDK 8). Natives
are kept to what Java cannot do: object identity, threads, I/O with the
platform, floating point formatting, and anything performance critical in
graphics.

- `nanojava.Boot` is the first Java code run: either a CLDC `main` (tests)
  or `nanojava.MIDletRunner`, which creates the MIDlet and runs the
  `Display` event loop on the boot thread.
- `javax.microedition.lcdui.Display` owns the screen back buffer, delivers
  input and paints. All application callbacks and painting are serialized
  with `Display.LOCK`.
- `LcduiBridge` and `MIDletBridge` are small public classes that give the
  `nanojava` package access to package-private lcdui/midlet internals.

## Graphics

Images are `short[]` pixels in the DS bitmap format (15-bit color, red in
the low bits, bit 15 set) plus an optional `byte[]` alpha plane. The RP2350
layer turns each presented frame into 8-bit palette slots (see below). `src/midp/gfx.c` draws all primitives,
blits with the 8 Sprite transforms and alpha blending; `font.c` draws the
built-in bitmap fonts generated by `tools/genfont.py` (DejaVu Sans).

## Sound

```
 Java (MMAPI)          nanojava.Audio natives        platform              synthesizer
 Player / Manager  ->  src/midp/natives_audio.c  ->  pal_audio_*  ->  src/audio/synth.c
                       src/audio/media.c                                 sound channels
                       (MIDI, WAV, tones -> events/PCM)
```

- `javax.microedition.media.PlayerImpl` keeps the MMAPI state machine,
  timing, looping and listener events in Java; the natives only decode,
  start, stop and set volumes.
- `src/audio/media.c` turns MIDI files into a flat list of channel events
  with absolute times in milliseconds (tempo map applied), MMAPI tone
  sequences into the same kind of list, and WAV into 16-bit mono PCM.
- `src/audio/synth.c` is a sequencer plus a synthesizer that does not mix
  samples: it plays notes on 16 DS-style hardware channels (looping 32
  sample waveforms with a pitch-dependent rate, PSG noise for drums, PCM
  for clips) and updates their volume and pitch for envelopes and MIDI
  controllers. General MIDI programs map to 16 families, each with a
  waveform (`src/audio/waves.h`, from `tools/genwaves.py`) and an ADSR
  envelope. It is integer-only.
- With a **General MIDI bank** (`gm_bank.bin`) bound, `src/audio/gmsynth.c`
  takes the songs' MIDI messages from the sequencer instead of the 16
  channels: xrip's wavetable engine (`external/embeded-midi-synth`) with one
  engine state (16 MIDI channels, 24 voices) per player slot, swapped in
  around every call.  It renders at the bank's rate, 31250 Hz, which is the
  mix rate of both platforms.  On the RP2350 the bank is read into the top
  of the PSRAM at boot (`platform/rp2350/gmbank.c`), outside the games'
  native heap; the host build takes `--gm-bank FILE`, and the tests play the
  audio MIDlet once more through a synthetic bank (`tools/make_test_bank.py`).
- On the **RP2350** (`platform/rp2350/audio_rp2350.c`) the synthesizer
  drives a software model of the 16 channels, mixed at 31250 Hz on core 1
  and sent to I2S or PWM in 8 ms DMA blocks. The VM's `pal_audio_*` calls
  (core 0) and the mixer share the synthesizer under a spin lock.
- On the **host** (`platform/host/audio_host.c`) the same synthesizer drives
  a software model of the DS channels mixed at 31250 Hz, which
  `--audio-out` records to a WAV file. The `audio` test MIDlet checks MIDI,
  WAV and tone playback this way.

## RP2350 layout

`platform/rp2350/`:

| File | Role |
|---|---|
| `main.c` | Start-up (clock, PSRAM, core 1), the launcher / game loop, starting and stopping the VM |
| `sys_rp2350.c` | `pal_sys.h`: the native heap in PSRAM (TLSF, `external/tlsf`), files through FatFs |
| `pal_rp2350.c` | `pal.h`: time, the console log, keyboard / gamepad to phone keys, the data directory |
| `video.c` | Frames to the VGA / HDMI driver, text mode for the menus |
| `video_tft.c` | The same for an SPI TFT panel (ST7789 / ILI9341, PIO program in `drivers/st7789`) |
| `input.cpp` | PS/2 and USB keyboards, NES/SNES pad (polled on core 1) |
| `audio_rp2350.c` | The channel mixer and `pal_audio_*` |
| `ui.c` | The game list, the emulator menu, the message / error screen |
| `settings.c` | Per-game settings in `/.config/pico-j2me/<game>.ini` |
| `psram.c` | QSPI PSRAM on QMI CS1: probe, size, timing |
| `memmap.ld` | The SDK linker script with the core 0 stack in main RAM and the hot VM code in SRAM |

The two cores:

- **Core 0** runs the launcher and the VM. Input reaches it through a
  lock-free ring filled by core 1 (`input_get`); `pal_wait` sleeps with
  `wfe` until the deadline or the next key (core 1 sends `sev`).
- **Core 1** runs the video driver's DMA interrupts, polls the PS/2
  keyboard, the gamepad and the USB host, and mixes the sound.

Memory:

- **PSRAM** (cached XIP window at 0x11000000): one TLSF pool for all native
  memory of a VM run - the Java heap (half of the PSRAM, at most 4 MB), the
  game's jar (read whole), class metadata, thread stacks, decoded sounds.
  The pool is recreated before each game, so nothing leaks between games.
  Without PSRAM the SRAM malloc is used with a 96 KB Java heap.
- **SRAM**: two 8-bit frame buffers (240x320 pixels at most), the text
  buffer, FatFs objects, the 16 KB core 0 stack (moved out of SCRATCH_Y by
  `memmap.ld`) and the hot code of the VM (interpreter, collector, class
  lookups, rasterizer, TLSF, mixer): the XIP cache is shared by the flash
  and the PSRAM, so code that runs from flash would compete with the heap.

Video: `pal_present` converts the 15-bit frame (in the Java heap) into
slots of a 5x8x5 colour cube (palette slots 0..199) in the frame buffer that
is not on the screen; core 1 switches buffers in the vertical blank. The
drivers' `GRAPHICS_SCALE_FIT` mode shows the canvas on the 640x480 screen
with the largest whole scale that keeps pixels square; canvases taller
than 240 rows use all 480 lines and 2 pixels per column. The launcher and
the menus use the driver's text mode (CGA colours in slots 200..215).

TFT build: the same 8-bit frame buffers; core 1 sends the newest finished
one to the panel a line at a time (palette lookup into a 16-bit line
buffer, DMA to the PIO serial program), returning to its main loop between
lines so input and sound keep running.  Frames that arrive meanwhile are
dropped.  The panel is not scaled: the screen is shown 1:1, the controller
is switched to portrait (MADCTL) for screens taller than 240 rows.  The
text mode is 53x30 cells of the 6x8 font, sent whenever it changes.

The emulator menu (F12 / Select) is opened from `pal_poll_event`, inside
the VM's polling: the VM is simply not scheduled while it is open, the VM
clock (`pal_time_ms`) is paused and the sound is muted.
